# Retirement modeler (the tool itself)

This repository is the tool: code, examples and templates. People's own plans live in plan folders *outside*
it (see README). Never copy personal data (statements, balances, names) into this repo; examples must stay
fictional.

## Invariants

- `modeler/model.py` (Python) and `modeler/build_workbook.py` (spreadsheet formulas) are two independent
  implementations of the same model. Change one, change the other, then rebuild the examples and run
  `./plan check examples/us` and `./plan check examples/ca`; both must say OK. That check is the whole test suite
  for the model, so run it after every change.
- The Model tab layout comes from `input_spec()` and `model_layout()` in build_workbook.py, and `workbook.py`
  reads workbooks with the same functions. Adding an input moves the rows below it. Existing plans built
  with the old layout then fail to read, with a clear error. Add new inputs at the end of a section, and
  mention layout changes in the commit message.
- Year-table column keys that model.py also returns are compared cell by cell; keep names identical.
- Tax law: new workbooks are seeded from `tax_tables.py`; after that the workbook's `tax_tables` tab is what
  both the formulas and the Python model read. Cite sources in the notes when changing amounts.
- Examples: `examples/<us|ca>/inputs/*.csv` -> `plan.xlsx` (`rm examples/us/plan.xlsx && ./plan build
  examples/us`). Statements are generated by `examples/make_sample_statements.py`. After changing either,
  run `./plan demo us` and `./plan demo ca` end to end.
- Workbooks must work in Excel, LibreOffice and Google Sheets. Use only functions all three support (no
  dynamic arrays, no MINIFS-style newer functions; SUMPRODUCT for array logic).
- Python 3.9+, standard library plus openpyxl.
